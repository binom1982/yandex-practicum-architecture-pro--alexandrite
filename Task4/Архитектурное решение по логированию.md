# Архитектурное решение по логированию

## Необходимые логи (уровень INFO)

| **Система** | **Событие**                                   | **Данные для логирования**                                                    |
| ------------------------ | ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Shop API                 | Создание заказа                              | время, ID покупателя, номер заказа, сумма                                |
| Shop API                 | Загрузка 3D-файла                             | время, ID заказа, размер файла, формат                                      |
| Shop API                 | Изменение статуса заказа             | время, номер заказа, старый статус, новый статус                 |
| CRM API                  | Подтверждение заказа                    | время, номер заказа, ID менеджера                                              |
| CRM API                  | Получение сообщения из MQ              | время, тип сообщения, ID заказа                                                  |
| MES API                  | Расчёт стоимости                            | время, номер заказа, количество полигонов, время расчёта |
| MES API                  | Назначение оператора                    | время, номер заказа, ID оператора                                              |
| MES API                  | Изменение статуса производства | время, номер заказа, статус, ID оператора                                |
| RabbitMQ                 | Публикация сообщения                    | время, топик, ID сообщения, ID заказа                                          |
| RabbitMQ                 | Получение сообщения                      | время, топик, ID сообщения, результат обработки                    |
| Shop DB                  | Запись заказа                                  | время, номер заказа, операция                                                   |
| MES DB                   | Обновление статуса                        | время, номер заказа, статус, операция                                     |

## Дополнительные уровни логирования

| **Уровень** | **Когда используется**                                                             | **Примеры**                                                                                                                               |
| ------------------------ | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| INFO                     | Нормальная работа системы                                                          | Создание заказа, изменение статуса, успешные API вызовы                                                    |
| WARN                     | Предупреждения, не требующие немедленного вмешательства | Медленные запросы (>2с), повторные попытки отправки в MQ, близкое исчерпание лимитов |
| ERROR                    | Ошибки, требующие внимания                                                         | Неудачные API вызовы, ошибки БД, потеря сообщений в MQ                                                          |
| DEBUG                    | Отладка (только в dev)                                                                      | Детали запросов, внутренние состояния, SQL-запросы                                                             |

## Мотивация

**Почему нужно добавить логирование:**

1. **Снижение времени на разбор инцидентов** — сейчас проблемы разбираются со слов клиента, что занимает много времени
2. **Уменьшение нагрузки на поддержку** — специалисты смогут самостоятельно анализировать логи
3. **Проактивное обнаружение проблем** — возможность настроить алертинг до того, как клиенты начнут жаловаться
4. **Улучшение наблюдаемости системы** — понимание потока заказов через все системы

**Технические и бизнес-метрики:**

| **Метрика**                                      | **Тип**       | **Ожидаемое влияние**      |
| ------------------------------------------------------------- | ---------------------- | ------------------------------------------------ |
| Время разбора инцидента (MTTR)           | Техническая | Снижение с часов до минут   |
| Количество обращений в поддержку | Бизнес           | Снижение на 30-50%                     |
| Время обнаружения проблемы            | Техническая | Снижение с дней до минут     |
| Процент потерянных заказов            | Бизнес           | Снижение до <0.1%                      |
| Время реакции на аномалии               | Техническая | Снижение с часов до секунд |

## Приоритет внедрения логирования и трейсинга

Поскольку команда не может реализовать всё одновременно, предлагаю следующий порядок:

| **Приоритет** | **Система** | **Обоснование**                                                                                                                                             |
| ---------------------------- | ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1                            | MES API + MES DB         | Основная проблема — заказы «зависают» в производстве, операторы жалуются на медленную работу |
| 2                            | RabbitMQ                 | Критично для отслеживания потери сообщений между системами                                                               |
| 3                            | Shop API                 | Точка входа заказов, важно для отслеживания проблем с новыми заказами                                             |
| 4                            | CRM API                  | Важно для работы менеджеров, но менее критично чем производство                                                        |
| 5                            | Shop DB + MES DB         | Дополнительная наблюдаемость за данными                                                                                                  |
