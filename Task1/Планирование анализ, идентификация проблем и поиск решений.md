# **Планирование: анализ, идентификация проблем и поиск решений**

## Проблемные места

**Существующие:**

1. **Потеря данных (Заказы):** Жалобы клиентов и API-партнеров на неполученные заказы. Вероятная причина: отсутствие гарантий доставки в RabbitMQ (ACK, DLQ).
2. **Производительность MES:** Долгая загрузка дашборда операторов. Причина: нагрузка на единственную БД (чтение + запись), отсутствие индексации или кеширования.
3. **Отказоустойчивость:** По одному инстансу на приложение (EC2) и БД. Single Point of Failure. Нет горизонтального масштабирования.
4. **Процесс релиза:** Ручное E2E-тестирование блокирует релизы. Задержки растут из-за багов уровня high/highest.
5. **Наблюдаемость:** Отсутствие мониторинга бэкенда и трейсинга. Невозможно отследить путь заказа между системами (Shop -> Queue -> CRM/MES).

**Потенциальные:**

1. Линейный рост нагрузки (+100 заказов/мес) усугубит проблемы с БД и очередями.
2. Расширение B2B API увеличит нагрузку на MES (расчет стоимости 2–30 мин).

## 2. Инициативы

1. Внедрение гарантий доставки сообщений в RabbitMQ (ACK, DLQ, Retry).
2. Оптимизация запросов MES и внедрение кеширования для дашборда.
3. Добавление реплик для БД (разделение чтения/записи).
4. Внедрение централизованного логирования и трейсинга.
5. Автоматизация тестирования (CI/CD pipeline).
6. Горизонтальное масштабирование сервисов (Auto Scaling).
7. Внедрение мониторинга метрик инфраструктуры и приложений.

## 3. Приоритизация

* **Приоритет 1 (Критический):** Надежность передачи заказов и наблюдаемость.
  *Обоснование:* Компания теряет контракты из-за потерянных заказов. Без трейсинга невозможно найти причину потерь.
* **Приоритет 2 (Высокий):** Производительность MES.
  *Обоснование:* Операторы не видят новые заказы, что тормозит производство и влияет на мотивацию.
* **Приоритет 3 (Средний):** Автоматизация тестов и масштабирование.
  *Обоснование:* Необходимо для поддержки роста нагрузки и ускорения релизов, но менее критично, чем текущие потери данных.

## 4. Целевая архитектура через полгода

* **Инфраструктура:** Контейнеризация сервисов, оркестрация для автокейлинга.
* **БД:** Master-Slave репликация для разделения нагрузки чтения (MES/Shop/CRM).
* **Интеграции:** Надежная шина событий (RabbitMQ с гарантиями доставки).
* **Observability:** Единое окно мониторинга (метрики, логи, трейсы) для всех сервисов.
* **Процессы:** Автоматизированный CI/CD с покрытием автотестами критических путей.

## 5. Топ-3 инициативы на полгода

1. Внедрение трейсинга и логирования.
   *Обоснование:* Позволит точно определить, на каком этапе теряются заказы. Без этого остальные оптимизации могут не решить корневую проблему.
2. Надежность RabbitMQ (ACK, DLQ).
   *Обоснование:* Прямое устранение причины потери заказов и жалоб API-партнеров.
3. Оптимизация MES (БД + Кеш).
   *Обоснование:* Устраняет bottleneck производства. Операторы смогут быстрее брать заказы, снижая очередь выполнения.
