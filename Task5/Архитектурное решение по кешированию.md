# Архитектурное решение по кешированию

## Мотивация

**Проблема:** Операторы MES жалуются на низкую скорость работы со страницей. При загрузке первой страницы MES (дашборд со списком заказов по статусам) система долго прогружается. Это критично, так как операторам важно видеть самые новые заказы — от этого зависит их вознаграждение.

**Причины проблем:**

1. MES DB (PostgreSQL) работает на запись и чтение с одного инстанса
2. При росте количества заказов (на 100 заказов в месяц) запросы к базе данных становятся медленнее
3. Фильтр по статусам и пагинация не решили проблему производительности

**Что планируется закешировать:**

* Список заказов в MES (дашборд операторов)
* Статусы заказов для отображения в интерфейсе
* Данные о заказах, которые часто читаются, но редко изменяются

**Ожидаемые выгоды:**

* Уменьшение нагрузки на MES DB
* Сокращение времени загрузки дашборда для операторов
* Повышение отказоустойчивости при пиковых нагрузках
* Улучшение пользовательского опыта операторов MES

## Предлагаемое решение

**Тип:** Серверное кеширование

**Обоснование:**

* Клиентское кеширование (в браузере оператора) не подходит, так как данные заказов меняются часто и должны быть актуальными
* Серверное кеширование позволяет контролировать актуальность данных и инвалидацию кеша централизованно
* Снижает нагрузку на базу данных при множественных запросах от разных операторов

### Паттерн кеширования

**Тип:** Cache-Aside

| Паттерн     | Обоснование                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Cache-Aside        | **Подходит:** <br />- данные загружаются в кеш только при запросе<br />- простая реализация, контроль над инвалидацией<br />- позволяет избежать загрузки ненужных данных в кеш<br />- простая логика инвалидации при изменении статуса заказа<br />- минимальные изменения в существующей архитектуре |
| ~~Write-Through~~ | **Не подходит:** требует записи в кеш при каждом изменении в БД, избыточно для читаемых данных                                                                                                                                                                                                                                                                                                                                                            |
| ~~Refresh-Ahead~~ | **Не подходит:** требует предсказания запросов, сложно реализовать для динамического списка заказов                                                                                                                                                                                                                                                                                                                                              |
